Mẫu i18n

“Locale trong URL” nghĩa là gì

Mỗi ngôn ngữ có URL riêng (/en/about, /vi/about) và file HTML prerender riêng. Link bạn chia sẻ mang theo ngôn ngữ, công cụ tìm kiếm lập chỉ mục cả hai, và trang đúng ngay lần vẽ đầu tiên — không lóe sai ngôn ngữ.

Cặp helper dễ nhầm nhất

Cùng một đầu vào, hai đối tượng khác nhau. Đưa getLocaleRoute cho component của Next (Link, router.push) — nó CHỈ thêm locale segment, vì Next tự thêm basePath. Đưa getLocalePath cho bề mặt thô (<a> thường) — nó trả về đường dẫn đầy đủ, basePath bao gồm.

GọiTrả về
getLocaleRoute("/about", "vi")/vi/about
getLocalePath("/about", "vi")/nextstatic/vi/about

Tĩnh trước: locale-in-route (không nhấp nháy)

Mỗi locale được prerender thành HTML riêng; provider nhận route param lúc build.

app/[locale]/layout.tsx
// app/[locale]/layout.tsx
export function generateStaticParams() {
  return locales.map((locale) => ({ locale }));
}

Chuyển locale

setLocale cập nhật state nhưng không điều hướng — tự push URL có locale.

client
// same-locale navigation — the lib router adds the locale segment
router.push("/about");

// switching locale — full URL (basePath + locale), on a raw anchor:
<a href={getLocalePath("/docs/", otherLocale)}>…</a>
Switch to English (raw anchor)
Liên kết này là <a> thô: đường dẫn qua Link trỏ tới locale hiện tại (trừ khi href đã sẵn mang một locale), còn <a> thô cần URL ĐẦY ĐỦ — getLocalePath dựng sẵn, gồm cả basePath, vì Next không thêm gì cho anchor thô.

Không cần provider

Link hoạt động độc lập: không có provider, locale rỗng và chỉ áp dụng basePath.
