One BASE_PATH feeds both Next and the lib; every wrapper prefixes correctly.

Imagine you host a Next.js static site on GitHub Pages. Its address is not https://user.github.io/ but https://user.github.io/your-repo/ — every URL must live under that /your-repo/ prefix. Next adds the prefix to its own chunks via basePath, but anything you write yourself — <a href="/about">, <img src="/logo.png">, url(/bg.png) in CSS — still points at the domain root. The result: broken images and 404s.

the same image, without and with the lib
✗ <img src="/logo.svg">      →  https://user.github.io/logo.svg          → 404
✓ <Image src="/logo.svg" /> →  https://user.github.io/your-repo/logo.svg → 200

nextstatic removes that manual work. Declare BASE_PATH once, feed it to both Next and the library, and every wrapper and util below prefixes paths automatically. Move the site to another host or folder — change one variable, rebuild.

The prefixing contract

Next primitives (Link, useRouter) add only the locale segment — getLocaleRoute. Next itself applies basePath.
Raw surfaces use the basePath-aware utils (getPrefixPath, getLocalePath).
