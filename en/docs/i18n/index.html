i18n patterns

What "locale in the URL" means

Each language gets its own URLs (/en/about, /vi/about) and its own prerendered HTML file. Links you share carry the language, search engines index both, and the page is correct on first paint — no flash of the wrong language.

The two helpers people mix up

Same input, two audiences. Hand getLocaleRoute to Next components (Link, router.push) — it adds ONLY the locale segment, because Next adds the basePath itself. Hand getLocalePath to raw surfaces (a plain <a>) — it returns the full path, basePath included.

CallReturns
getLocaleRoute("/about", "vi")/vi/about
getLocalePath("/about", "vi")/nextstatic/vi/about

Static-first: locale-in-route (zero flicker)

Each locale is prerendered as its own HTML; the provider receives the route param at build time.

app/[locale]/layout.tsx
// app/[locale]/layout.tsx
export function generateStaticParams() {
  return locales.map((locale) => ({ locale }));
}

Switching locale

setLocale updates state but does not navigate — push the localized URL yourself.

client
// same-locale navigation — the lib router adds the locale segment
router.push("/about");

// switching locale — full URL (basePath + locale), on a raw anchor:
<a href={getLocalePath("/docs/", otherLocale)}>…</a>
Chuyển sang tiếng Việt (raw anchor)
This link is a raw <a>: paths routed through Link target the current locale (unless the href already carries one), but a raw <a> needs the FULL URL — getLocalePath builds it, basePath included, because Next adds nothing to a raw anchor.

No provider needed

Link works standalone: without a provider the locale is empty and only the basePath applies.
