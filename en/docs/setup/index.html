Setup

Four steps from zero to a correctly-prefixed static site.

Install

terminal
npm install @hieupth/nextstatic

Next.js 16.3+ using static export (output: "export") · React 18 or 19 · Node.js 22 or newer

Pick your BASE_PATH

BASE_PATH is the slice of the URL between the domain and your app. It has to match where you host — the table below lists the common cases.

HostingSite URLBASE_PATH
Root of your own domainhttps://my-site.com/""
GitHub Pages project sitehttps://user.github.io/repo/"/repo"
A sub-folder (like this preview)https://host/demo/"/demo"

On GitHub Actions you can infer it from GITHUB_REPOSITORY — see the repo's own next.config.ts for the ready-made snippet.

Wire up next.config.ts

The same value must reach Next (basePath) and the library (env) — that is the whole "they must agree" contract. The env block inlines the value into the client bundle so the lib reads the exact same prefix at runtime.

next.config.ts
const basePath = process.env.BASE_PATH ?? "";

const nextConfig = {
  // static files only — no Node server needed
  output: "export",
  // /about/ style URLs → about/index.html on disk
  trailingSlash: true,
  // Next prefixes its own chunks & routes…
  basePath,
  assetPrefix: basePath,
  images: { unoptimized: true },
  // …and the env block inlines the value so the lib
  // reads the SAME prefix at runtime
  env: {
    BASE_PATH: basePath,
    NEXT_PUBLIC_BASE_PATH: basePath,
  },
};

Build and verify

Build with a base path
BASE_PATH=/demo npm run build

Open the built site — the footer shows the live BASE_PATH, and every image must load under that prefix.

That is the whole setup. Everything else is handled by the wrappers.
